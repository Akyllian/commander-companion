# R3 Mazzi Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Mazzi placeholder with a local grimoire. A pasted list is recognised through Scryfall and saved for offline use. Each deck shows its commander, deterministic categories, the list, strategy notes, key cards and a London-mulligan test hand, and can be linked to a player without taking over the match.

**Architecture:**
- **Pure domain** in `src/decks/*.ts`, all at 100% coverage: list parser, deck model and validation, category engine, mulligan engine, storage. Views live in `src/decks/ui/` and are covered by component tests, outside the 100% glob.
- **Storage:** decks and card data live in a new IndexedDB database (`commander-companion-decks`, stores `decks` and `cards`). Art crops reuse the existing art store, and their ids join its keep-set.
- **Scryfall:** recognition goes through the existing adapter with the shared 125 ms limiter, using `/cards/collection` (75 identifiers per request) and a multilingual exact search only for names it could not find.
- **Match link:** the link to a player lives in the game record (schema v6), so reload, other tabs, reset and removal all follow the reducer's rules.
- **UI:** four views under `#mazzi` (Libreria, Importa, Dettaglio, and the Seleziona mazzo sheet in Partita) with hash sub-paths, so Back returns to the library.

**Tech Stack:** React 19, TypeScript 7, CSS, IndexedDB (`fake-indexeddb` in tests), Vitest, Testing Library, fast-check

**Spec:** `docs/superpowers/specs/2026-10-21-r3-decks-design.md`, with the board `docs/art-direction/r3-decks-board.svg`. All 15 decisions of §19 were approved by the product owner on 2026-10-21. Kept unchanged: D-025, D-031, D-037, D-038, D-039.

## Global Constraints

- **Copy:** Italian, using the spec's exact strings. Card names stay as Scryfall returns them.
- **Targets:**
  - every action is at least 44×44 px;
  - openable rows and search results are at least 56 px;
  - library rows are at least 88 px (`--deck-row-min-height`).
- **Art (D-025):**
  - `art_crop` only: never full cards, frames, mana-cost boxes or rules boxes in the hand;
  - the artist is credited in the hero, in result rows and in every hand card's Dettagli sheet;
  - no prices, scores, percentages or advice;
  - no AI-generated text or categories.
- **Icons and colour:** monochrome line icons. No new colours for categories, rarity, owner or offline state. The F34 exception stays limited to mana symbols (D-039).
- **Network:**
  - Scryfall is called only from `src/media/scryfall.ts`, always through the shared 125 ms limiter;
  - **one build-time exception:** the developer script `scripts/fetch-category-fixtures.mjs` (Task 4). It is never imported by the app or the tests. It uses the same 125 ms gap and sends `Accept: application/json` and `User-Agent: CommanderCompanion-fixtures/1.0`, as Scryfall's guidelines require;
  - analysis starts only on an explicit action, never per keystroke;
  - images are downloaded only from `cards.scryfall.io`.
- **Offline:** a prepared deck is fully usable offline. There are three states: `complete`, `partial` («Offline senza tutti i ritagli») and `incomplete` («Preparazione incompleta»). A card with no `art_crop` at Scryfall counts as complete and uses the neutral texture.
- **Commander rule:** the commander (and Partner) must be in the saved list and are excluded from the drawable library. Legality is never certified; the app shows «Legalità non verificata dall'app».
- **Measures:**

  | Token | Value |
  | --- | --- |
  | `--deck-hero-height` | 168px (220px from tablet) |
  | `--deck-art-size` | 64px |
  | `--hand-crop-width` | `clamp(7rem, 31vw, 8.5rem)` |
  | `--duration-deck-step` | 180ms |
  | `--duration-hand-deal` | 160ms |
  | `--duration-hand-out` | 120ms |
- **Motion:**

  | Event | Duration | Properties |
  | --- | --- | --- |
  | Tab change | 140ms | crossfade, ≤ 2px settle |
  | Crop appears | 140ms | opacity |
  | Import step | 180ms | opacity, ≤ 6px translateX |
  | Hand | 160ms per card | 20ms stagger, ≤ 280ms total |
  | Mulligan exit | 120ms | opacity |

  No flips, bounces or particles. Reduced motion makes every step immediate.
- **Schema:** the game schema bumps to v6 with a pure, tested migration. Every new stored payload is validated as unknown input.
- **Dependencies and scope:** no new dependencies. Do not start R4.

## Review Focus

1. **Storage quota runs out halfway through preparing a deck.** The deck is never declared offline; «Lo spazio del dispositivo non basta per tutti i ritagli» offers «Salva senza tutti i ritagli» or «Annulla»; nothing already typed is lost. Pinned in Task 5.
2. **A linked deck is deleted, or its player is removed, while a match is running.** The applied commander and art stay. The field shows «Mazzo non disponibile». Removing the player drops only that seat's link. Pinned in Tasks 6 and 13.
3. **Double-faced, split and Partner cards.**
   - One record per card, names joined with ` // `.
   - Categories read every face.
   - A DFC commander takes the front face's crop.
   - Both Partners are excluded from the library.
   Pinned in Tasks 3, 4 and 7.
4. **The same name listed twice with different printings** (`1 Sol Ring (CMM) 396` and `1 Sol Ring`). Both lines keep their own printing and quantity; categories count the card once per copy. Pinned in Tasks 2 and 3.
5. **A reload or closed tab in the middle of an import.** The draft (text, Verifica choices, Dettagli fields) comes back once with «Bozza di importazione recuperata», and a resumed download does not duplicate the deck. Pinned in Tasks 5 and 9.

### Task 2: List parser

**Files:**
- Create: `src/decks/parseList.ts`, `src/decks/parseList.test.ts`

**Interfaces:**
- Produces:
  - `ParsedSection = 'commander' | 'main' | 'excluded'`;
  - `ParsedLine`:
    ```ts
    type ParsedLine =
      | { kind: 'card'; section: ParsedSection; sectionName: string | null; quantity: number; name: string; set: string | null; number: string | null; source: string; line: number }
      | { kind: 'invalid'; source: string; line: number }
    ```
  - `parseList(text: string): ParsedLine[]`.

The grammar follows spec §5.2 exactly, after trimming each line and collapsing runs of whitespace:

| Input | Result |
| --- | --- |
| `N Name` | a card |
| `Nx Name` / `NX Name` | a card |
| `N Name (SET) COLLECTOR` | a card with its printing: `SET` 2–6 alphanumerics, `COLLECTOR` alphanumerics plus `-★`; the set is lowercased for Scryfall |
| `Commander`, `Mainboard`, `Sideboard`, `Maybeboard` (any case, optionally in `[...]` and with a trailing `:`) | a heading |
| `Considering` | a heading, mapped to `excluded` |
| empty line | ignored |
| anything else | `invalid` |

- **Allowed punctuation variants** (the only ones the spec lets Claude add):
  - a trailing `:` on headings;
  - a tab instead of a space after the quantity;
  - Windows line endings;
  - a leading BOM.
- **Section order:** lines before any heading are `main`. Excluded sections keep `sectionName`, so Verifica can show «Sezioni non importate».

- [ ] **Step 1: Write the failing tests:** one fixture per accepted format above, plus:
  - Review Focus 4: two printings of the same name stay two lines;
  - `0 Sol Ring`, `Sol Ring` without a quantity and `1` alone are `invalid`;
  - `Commander` followed by two cards gives two `commander` lines;
  - `[Sideboard]` lines are `excluded` with `sectionName: 'Sideboard'`;
  - line numbers are 1-based and match the source.
- [ ] **Step 2: Run** `npx vitest run src/decks/parseList.test.ts`. Expected: FAIL.
- [ ] **Step 3: Implement** with a small regex per line, no state beyond the current section.
- [ ] **Step 4: Run.** Expected: PASS, 100%.

### Task 3: Card recognition through Scryfall

**Files:**
- Modify: `src/media/scryfall.ts`, `src/media/scryfall.test.ts`
- Create: `src/decks/recognize.ts`, `src/decks/recognize.test.ts`

**Interfaces:**
- Produces `CardData` in `scryfall.ts`, one per printing:
  ```ts
  interface CardData {
    cardId: string
    name: string        // ' // ' between faces
    printedName: string | null
    typeLine: string    // all faces, ' // '
    oracleText: string  // all faces, '\n'
    manaCost: string    // front face, or '' when absent
    artist: string      // front face
    artUrl: string | null // front face art_crop, only on cards.scryfall.io
    set: string
    number: string
  }
  ```
- Produces `toCardData(card: unknown): CardData | null`. It maps a **raw Scryfall card object** only.
- Produces `parseCardData(value: unknown): CardData | null`, which validates the app's own normalised `CardData` shape as read back from IndexedDB:
  - every field has its type;
  - `cardId` is a UUID;
  - `artUrl` is null or on `cards.scryfall.io`;
  - strings are bounded (names ≤ 200, oracle text ≤ 4 000).

  `toCardData` is never run on stored entries.
- Produces `fetchCollection(identifiers: Array<{ name: string } | { set: string; collector_number: string }>, fetchImpl?)`:
  - `POST ${API}/cards/collection` with JSON `{ identifiers }`, at most 75 per call, through the limiter;
  - returns `{ found: CardData[]; notFound: unknown[] }`.
- Produces `searchLocalized(name, fetchImpl?)`:
  - `GET ${API}/cards/search?include_multilingual=true&q=${encodeURIComponent(`!"${name}"`)}`, through the limiter;
  - keeps the cards whose `printed_name` or `name` equals `name`, ignoring case and accents;
  - deduplicates by `cardId`;
  - sorts stably by English `name`, then `set`, then collector `number` (numeric, then text);
  - returns at most **five** options, the D-027 result-list limit.
- Produces `recognize(lines: ParsedLine[], deps): Promise<Recognition>` in `recognize.ts`, where `Recognition` holds:
  - `matched: Array<{ line: ParsedLine; card: CardData }>`;
  - `ambiguous: Array<{ line: ParsedLine; options: CardData[] }>`;
  - `missing: ParsedLine[]`;
  - `excluded: ParsedLine[]`;
  - `invalid: ParsedLine[]`.

  It works in three passes:
  1. lines with a set and number are identified by printing;
  2. the remaining names go by `{ name }`, in chunks of 75;
  3. each name still not found runs one `searchLocalized`: one result is a match, several distinct results are `ambiguous` («Scegli una corrispondenza»), none is `missing`.

  A network error is thrown as `ScryfallError('network')`, and the caller keeps the text intact.

**Files:**
- Create:
  - `src/decks/deckStore.ts`, `src/decks/deckStore.test.ts`;
  - `src/decks/prepareOffline.ts`, `src/decks/prepareOffline.test.ts`;

**Interfaces:**
- Produces from `deckStore.ts`:
  - `DECKS_DB_NAME = 'commander-companion-decks'`, with stores `decks` (key `id`) and `cards` (key `cardId`);
  - `DeckStore { listDecks(); getDeck(id); putDeck(deck); deleteDeck(id); getCards(ids): Map<string, CardData>; putCards(cards) }`;
  - `createIndexedDbDeckStore(factory)`, `getDeckStore()`, `setDeckStoreForTests()`;
  - every read goes through `parseDeck` (decks) or `parseCardData` (cards), and invalid records are skipped.
- Produces from `prepareOffline.ts`:
  ```ts
  prepareOffline(
    deck: DeckRecord,
    cards: CardData[],
    deps: { art: ArtStore; download: (url) => Promise<Blob>; analyze; onProgress(done, total) },
  ): Promise<{ offline: OfflineState; missing: string[]; reason: 'network' | 'quota' | null }>
  ```
  - downloads sequentially every `artUrl` not already in the art store, resuming where it stopped;
  - stops on the first network error (`incomplete`, reason `network`);
  - a `QuotaExceededError` from IndexedDB gives `partial` with reason `quota`;
  - cards with `artUrl: null` count as done.
- Produces `deckArtIds(decks: DeckRecord[], cards: Map<string, CardData>): Set<string>`: commander and card art of every deck.
- **First prune of the art store** (cold start, fix 1):
  - `useMatchArt` takes a third argument, `deckArt: Set<string> | 'loading' | 'unavailable'`;
  - the one prune runs only once both the match envelope's fill has settled **and** `deckArt` is a `Set`;
  - its keep-set is the union of the match envelope, every player's commanders and `deckArt`;
  - if the deck store cannot be opened or read, `deckArt` is `'unavailable'` and the prune is **skipped** for that session, so cached deck art is never deleted by mistake.
- Produces from `importDraft.ts` (localStorage key `commander-companion.import-draft`, validated):
  ```ts
  interface ImportDraft {
    step: 1 | 2 | 3
    text: string
    textHash: string | null // null until the first successful analysis
    // the analysis result as line → cardId; the CardData live in the `cards` store
    recognition: { matched: Record<number, string>; ambiguous: Record<number, string[]>; missing: number[] } | null
    choices: Record<number, string>
    ignoredLines: boolean
    acceptedMissing: boolean
    details: { name; owner; commanders; notes }
  }
  ```
  - `saveDraft`, `loadDraft`, `clearDraft`;
  - `hashText(text)` hashes the text after normalising **only** line endings (`\r\n` and `\r` → `\n`). Empty lines, line order and spaces are preserved, because the draft keys its choices by line number;
  - `draftForText(draft, text)`: when `hashText(text)` differs from `textHash`, it drops `recognition`, `choices`, `ignoredLines` and `acceptedMissing` and goes back to step 1. Any edit other than a line-ending change invalidates old choices (fix 2).
- **The analysis is saved as it happens** (fix 2): `ImportDeck` calls `store.putCards()` with every recognised and ambiguous `CardData` right after the analysis, before Verifica renders. A draft at step 2 therefore restores **offline** from the draft plus the `cards` store, with no new request.

## Calls made in this plan (for review)

1. **Link storage.** The link lives in the game record (schema v6), not in a separate store, so undo history, other tabs, reset and removal follow the reducer's rules. On a confirmed new game, `carryDeckLinks` keeps each surviving seat's link and re-applies the deck. This is how «proposto alla prossima nuova partita» (§11.2) is read.
2. **Decks in IndexedDB.** Decks and their card data go in IndexedDB, not localStorage: ten decks with card data exceed what localStorage reliably holds, and crops already live in IndexedDB.
3. **Recognition.** `/cards/collection` handles 75 cards per request (two requests for 100 cards). Only unresolved names go to `include_multilingual` exact search, so a localized list costs one request per localized name, all at 125ms intervals.
4. **Categories.** They read the English oracle text after reminder text is removed, with the regex matrix above. Fixtures are real Scryfall texts, fetched once by a committed script. No category comes from a model, and equal data always gives equal results.
5. **Autosave.** Strategy notes save 600ms after the last keystroke and on blur.
6. **Duplicate names.** The same name with two printings stays as two lines: quantities are not merged across printings, so the list matches what was pasted.
