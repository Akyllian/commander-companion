# R1 App Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the single-screen score keeper into a four-section app (Partita, Mazzi, Impara, Altro) with a top navigation bar, a central rhombus that reveals it during play, a complete Altro/Impostazioni screen and honest placeholders, without touching R2 features.

**Architecture:** `App` becomes a shell. A small hash-based section hook (`#mazzi`, `#impara`, `#altro`, empty = Partita) drives which view is visible. The game view stays mounted and is only `hidden`, so panels never remount. Header, Undo/Redo, the removal Undo bar, `TableControls`, `MatchMenu`, `PreferencesMenu`, the layout side sheet and the footer go away. Their functions move to `MoreScreen`. The rhombus position and the free zone each panel keeps around it come from one pure geometry module, measured at runtime, so they hold in every layout and responsive column count.

**Tech Stack:** React 19, TypeScript 7, CSS (`@starting-style`, `transition-behavior: allow-discrete`, top layer), Vitest, Testing Library, localStorage

**Spec:**
- Product: `docs/superpowers/specs/2026-10-20-app-restructure-design.md` (D-037, approved 2026-10-20).
- Design: `docs/superpowers/specs/2026-10-20-r1-shell-design.md`, with the board `docs/art-direction/r1-shell-navigation.svg` (approved 2026-10-20, Regole bridge kept in Impara until R4).

## Global Constraints

- All UI copy in Italian. Section labels exactly: `Partita`, `Mazzi`, `Impara`, `Altro`.
- Fixed DOM and visual order: Partita, Mazzi, Impara, Altro. `nav` with `aria-current="page"`, never `role="tab"`.
- Bar height: 60px, or 52px in compact density, plus `env(safe-area-inset-top)`. Each item is at least 48×48px with a visible label at every size, including 844×330. Labels use the utility face, 0.72rem / 0.68rem compact, uppercase, tracking 0.08em.
- Inactive items: muted ivory. Active: warm gold with a 2px underline. Opaque ink surface with a gold hairline; no glass, no strong glow, no capsule or bottom bar.
- Bar motion: enter 180ms (opacity, `translateY(-8px → 0)`, `--ease-out`); exit 140ms (opacity, `translateY(−4px)`). Active line 140ms. Section change: 140ms crossfade with a 2px settle. Rhombus: press 90ms, opening glow 140ms, no rotation, no pulse. Reduced motion: immediate.
- Rhombus: a real `<button>`, 56×56px, upright to the viewport. `aria-label` `Mostra le sezioni` / `Nascondi le sezioni`, plus `aria-expanded` and `aria-controls`. No long press or gestures.
- Free zone of at least 64×64px around the rhombus. Panels keep the card proportions of D-034/D-035: no visible notch and no 64px gap.
- Hidden bar = no focusable descendants. During play the revealed bar never reflows or remounts the panels.
- Targets ≥ 44px, WCAG AA (4.5:1 labels, 3:1 icons and borders), line icons only, D-032 danger rules (filled red only inside the confirmation dialog).
- Wake Lock is held only while Partita is the visible section and the preference is on.
- Do not add dependencies. Do not start R2: no new player card, counter drawer, dice, mana or coin flip.

## Review Focus

1. **Reloading or using Back on `#altro`** returns to Altro, and Back from there returns to Partita with the same scores. Pinned in Task 2.
2. **Hiding the bar while focus is inside it** (Esc, tapping Partita, tapping the rhombus) leaves focus on the rhombus, never on `<body>`. Pinned in Task 6.
3. **Starting a new game from Altro with a different player count** switches the layout options shown in Altro to the new table and keeps both saved layout preferences. Pinned in Task 4.
4. **Three players in a single portrait column** (odd count): the rhombus sits on the seam nearest the centre, never on the middle panel's life total. Pinned in Task 7.
5. **System notices during play** (update available, save failed) appear as a toast that never covers the rhombus or a panel's controls, and stay reachable. Pinned in Task 6.

### Task 7: Rhombus placement and the 64px free zone

**Files:**
- Create: `src/shell/centre.ts`, `src/shell/useCentreLayout.ts`
- Modify: `src/components/PlayerSeat.tsx` (optional `clear` prop → `data-clear`), `src/App.tsx` (position the rhombus from the hook)
- Test: `src/shell/centre.test.ts`

**Interfaces:**
- Produces, in `centre.ts`:
  - `type Point = { x: number; y: number }` and `type Box = { left: number; top: number; right: number; bottom: number }`;
  - `type Clearance = 'top-start' | 'top' | 'top-end' | 'end' | 'bottom-end' | 'bottom' | 'bottom-start' | 'start'`.
- Produces `rhombusPoint(grid: Box, panels: Box[]): Point`:
  - start from the centre of `grid`;
  - if that point lies inside a panel (odd stacked counts), snap vertically to the nearer horizontal seam of that panel, the midpoint of the gap to its neighbour above or below.
- Produces `clearanceFor(panel: Box, point: Point, reach: number, orientation: Orientation): Clearance | null`:
  - `null` when the 64px zone centred on `point` (`reach = 32`) does not touch the panel;
  - otherwise the panel side or corner it touches, expressed **in the panel's own frame**. 180° swaps both axes; 90°/−90° rotate the sides; `start`/`end` are the inline sides of the unrotated card.
- Produces `useCentreLayout(gridRef, panelSelector)`, which returns `{ point: Point | null, clearances: (Clearance | null)[] }`:
  - measured with `ResizeObserver` and on layout change;
  - all values relative to the grid;
  - `null` before the first measurement.
- CSS (Task 8) reserves room for each `data-clear` value by padding only the panel's first row (top values) or last row (bottom values) on the right side. Mid-edge values (`start`, `end`) pad the life row. That keeps the cards' outer geometry unchanged.

- [ ] **Step 1: Write the failing tests** for `rhombusPoint` and `clearanceFor`, using concrete boxes:
  - 2×2 grid of 200×120 cards with an 8px gap: point (204,124); clearances `bottom-end`, `bottom-start`, `top-end`, `top-start`.
  - The same grid in Fronte a fronte (orientations 180, 180, 0, 0): `top-start`, `top-end`, `top-end`, `top-start`.
  - Two side-by-side cards: `end` and `start`.
  - Two stacked face to face (0 bottom, 180 top): both `top`.
  - Tavolo (centre cell empty, side cards ±90): every value `null`.
  - Three stacked cards in one column (odd): the point lands on a seam and the middle card gets `top` or `bottom`, never `null` inside its life area.
  - A 64px zone that misses a far card: `null`.
